# 踩坑总账（按症状查）

> 这些全是**本机真实撞到的**，不是抄来的清单。每条给「症状 → 真因 → 解法」，能省你几个小时。
> 环境：Windows 11 中文版、PowerShell 5.1（不是 7）、Node 24.21.0、pnpm 11.28.5、DSH 0.2.1-rc.2。

---

## A. PowerShell / Windows 本身

| # | 症状 | 真因 | 解法 |
| --- | --- | --- | --- |
| A1 | 中文 `.ps1` 一跑就 `Unexpected token '}'` / `The string is missing the terminator`，报错行里的中文全是 `璇峰厛鍚姩` 这种乱码 | **PowerShell 5.1 把无 BOM 的 UTF-8 当 ANSI 解码**，中文把引号配对搞乱 | 脚本存成 **UTF-8 with BOM**：`[IO.File]::WriteAllBytes($p, ([byte[]](0xEF,0xBB,0xBF) + [IO.File]::ReadAllBytes($p)))`；存完校验前三字节 `239,187,191` |
| A2 | 安装脚本每步都"失败"，但手动跑 pnpm 明明成功 | **pnpm 把进度写 stderr**，而 `$ErrorActionPreference='Stop'` 把原生命令的 stderr 当终止性错误 | 包一层 `Invoke-Dsh`：进入时把 EAP 降到 `Continue`，`2>&1 | Out-String` 收输出，只看 `$LASTEXITCODE` |
| A3 | `Invoke-WebRequest` 抓任何网页都失败，报"Windows PowerShell 处于非交互模式。朗读和提示功能不可用。" | PS 5.1 的 IWR 走 **IE 引擎**，非交互环境里初始化失败 | 一律用 `Invoke-RestMethod`（或 `curl.exe`）。我在抓 GitHub README 时被这条坑了整整一轮 |
| A4 | 用 `Invoke-RestMethod` 提交中文 JSON，存进去变成 `????` | 字符串被按 ANSI 编码发送 | `-Body ([Text.Encoding]::UTF8.GetBytes($json))`，别直接传字符串 |
| A5 | 沙箱下任何 pwsh 命令都失败：`SetNamedSecurityInfoW failed (Win32 5): grantWrite(...)` | 文件沙箱给工作区授权时 ACL 设置失败（中文路径 + 继承） | 要么放宽策略（`danger-full-access`），要么先修 ACL（见 `diagnose-windows-sandbox-acl` 技能） |
| A6 | `ConvertFrom-Json` 读插件 `package.json` 报错 / 字段变乱码 | 同上，PS 5.1 按 GBK 解码 UTF-8 | 先用 `Get-Content -Raw -Encoding UTF8` 读成字符串再 `ConvertFrom-Json` |
| A7 | 日志"乱码"，`涓诲姩璇磋瘽` 这种 | 文件是 UTF-8，`Get-Content` 默认按 ANSI 读 | `Get-Content ... -Encoding UTF8`（我的 `watchdog.ps1` 里所有读日志都带这个参数） |
| A8 | `winget install Gyan.FFmpeg` 失败：`copy_file: Access is denied` | winget 往 `WinGet\Packages` 复制时被拦 | 直接下 GitHub release zip 解压，再把 `bin` 加进配置（我用 `bili.ffmpegPath` 显式指定） |
| A9 | 服务"刚才还在听，一测就 `ECONNREFUSED`" | `Start-Process` 起的子进程挂在**调用方作业对象**上，父进程（尤其是后台作业）一被回收，子进程跟着死 | 用 `cmd /c start "名字" /min "exe" args` 彻底脱钩 |
| A10 | 一条命令把自己杀了，退出码 `4294967295` | 用 `CommandLine -match 'watchdog.ps1'` 找进程时，**当前这条 pwsh 的命令行里也含这个关键字** | 用更严的正则 `'\-File\s+"?[^"]*watchdog\.ps1'` 并排除 `$PID` |
| A11 | `node onebot-call.mjs send_private_msg '{"user_id":123}'` 报 `params 不是合法 JSON: Expected property name` | PowerShell 把 JSON 里的双引号吞了 | 写成 `'{\"user_id\":123}'`，或者把 JSON 落到临时文件再传路径 |
| A12 | `$x = $proc.Count > 0` 之后 `$x` 是 `$null`，还多出一个**名为 `0` 的空文件** | PowerShell 把 `>` 当**重定向**解析了 | 用 `-gt`：`$x = $proc.Count -gt 0`（我就这么生成过一个 `0` 文件，还得手动删） |
| A13 | Windows 凭据里的 git 凭据能用，但 `git push` 说找不到 helper | `credential.helper=manager` 但 `git-credential-manager` 不在 PATH | 装 Git Credential Manager，或改用 PAT / SSH |

## B. DSH 本体（插件、profile、会话）

| # | 症状 | 真因 | 解法 |
| --- | --- | --- | --- |
| B1 | `dsh plugin --profile desktop add x` 报 `profile "desktop" is managed exclusively by the Electron application` | 桌面端独占该 profile | 要么在 GUI 里装，要么改用别的 profile 做实验（`web`/`headless`） |
| B2 | 插件装上了、依赖也在，但 DSH 里毫无反应 | 只加了 dependency，**没进 `dsh.profile.bundles`** | 三个概念：`package.json`（依赖）+ `dsh.profile.bundles`（加载清单）+ `cordis.patch.yml`（配置补丁层）。装完必须核 bundles |
| B3 | 报 `no agent factory registered` | profile 里混进了 `@deepseek-ai/dsh-headless`，它的 headless-startup 会把 `credentials/authorization/deepseek-account` 关掉，agent-loop 构造不起来 | 从 bundles 里移除 headless（我就是这么把旧桥救回来的） |
| B4 | 自己写脚本解 DSH 会话 `session.jsonl.zstd`，只解出第一行 | **多帧 zstd** 布局，`zlib.zstdDecompressSync` 只处理第一帧 | 别自己解，用 `dsh` 自己的读会话能力；或逐帧 `ZSTD_findFrameCompressedSize` |
| B5 | 装了某个插件后 DSH 启动不了 / 行为诡异 | 插件声明了 `@deepseek-ai/*` 依赖，pnpm 在 `node_modules` 里落了**第二套核心实例** | 只装 peer 依赖为 `*`/`^0.2.x` 且**自带 `dsh.bundle.patch`** 的插件；没 `bundle.patch` 的老式插件坚决不装 |
| B6 | DSH 报 `Unexpected token ''` | profile 的 `package.json` 存成了**带 BOM** | 去掉 BOM（这个坑上游两个项目 README 都记了） |
| B7 | 想装最新版，pnpm 却装了旧版本 | pnpm 的 **minimumReleaseAge** 供应链闸门（新发布包默认冷却期） | 在 `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 里按 `包名@版本` 加白 |
| B8 | 脚本里硬编码 `http://127.0.0.1:62707/aurabot/api`，下次启动全 404 | **DSH web 端口每次启动都变** | 从 DSH 窗口/日志/`Get-NetTCPConnection` 动态拿；面板 API 永远挂在 `/aurabot/api` 下 |
| B9 | 卸载插件后 bundles 里还留着、搜索服务还占着 `web_search` 默认实现 | 有的插件卸载不干净 | 装前记快照（`dsh-undo-savepoint`），出问题直接回滚；或用 `undo_list` / `undo_restore` |

## C. Aurabot（面板 API / 配置 / 模块）

| # | 症状 | 真因 | 解法 |
| --- | --- | --- | --- |
| C1 | `POST /save` 想清空一个密钥，传 `''` 没反应 | `mergeFromPanel` 的规则：**密钥字段空串 = 保留原值，只有 `null` 才清空** | 传 `null`；判断"配没配"看 `xxxSet`，看提示看 `xxxHint`（末尾 4 位） |
| C2 | B 站显示 `canPost:true`，实际发评论还是失败 | `duty.js:55` 的 `canPost` **只检查 cookie 串里有没有 `bili_jct`**，不代表登录有效 | 看 `account.isLogin`；我填过假值验证过这个陷阱 |
| C3 | 调某个模块接口，回「这个功能所在的模块没开」 | **路由不存在也会回这句**（`core/modules.js:562` 的兜底），会被误判成模块被关 | 先用 `GET /modules` 看真实路由名，别猜 `/xxx/state` |
| C4 | 想用 `/modules/simulate` 测内置命令，只回「这是内置命令，模拟里不执行」 | 内置命令会真改设置，所以模拟器拒绝执行 | 内置命令只能单测解析层（`src/chat/commands.js` 的 `parseCommand`） |
| C5 | 自己写的本地接口脚本报错，却只看到 `log.warn is not a function` | 插件的 `local.js` catch 里调用了不存在的 `log.warn`，**把你的真实错误吞了** | 去 `/local/status` 的 `last.message` 里看真因 |
| C6 | `edge_tts --rate -8%` 直接报 argparse 错 | 空格开头被当成选项 | 必须写成 `--rate=-8%`（带等号） |
| C7 | 模块命令 `/饭碗` 被解析成了别的 | `parseCommand` 先做**中文别名前缀匹配** | 把更精确的命令名注册在别名之前（`ricebowl` 放 `rice` 前面） |
| C8 | 看日志时被几万字符的 base64 糊满屏幕 | 表情同步失败时会把 base64 打进日志行 | 永远 `Select-String` 过滤，别整段 `Tail` 打印 |
| C9 | 抖音登录页二维码一直是"已失效，点击刷新" | `site.js:604 loginStart()` 只"点右上角登录一次"，弹窗已开着时不会刷新 | 用 `tools/douyin-qr-refresh.mjs` 走 CDP 点「点击刷新」再截图 |
| C10 | 她回复里该发表情却跳过 | 表情标签和库里对不上（日志 `没找到「xx」这张表情`） | 标签用库里的词（我库里是 `白米饭/得意/无语/嫌弃/卖萌` 这类），或先 `/sticker/upload` 入库 |
| C11 | 面板显示"没开语音输入插件"，但语音明明能转 | 那说的是 DSH 的 `speechToText`（第三段兜底）；本地 ASR 是**第一段**，不受影响 | 看 `/local/status` 的 `asr.active` |
| C12 | 工作区里找不到聊天记录 | 她的会话落在 DSH 的 **storage**（工作区 `Aurabot · QQ` → `%USERPROFILE%\Aurabot\qq-chats`），**不按聊天建目录** | 记忆在插件库（`plugins-data/aurabot/`），日记由 diary 模块发说说，别去旧方案的 `QQ会话\私聊_xxx\` 找 |

## E. 语音（TTS / ASR）

| # | 症状 | 真因 | 解法 |
| --- | --- | --- | --- |
| E1 | faster-whisper 一调用就 `TypeError: open() got an unexpected keyword argument 'metadata_errors'` | 它的解码走 `av`，和 Python 3.13 上的 av 19 不兼容；而 `av==14.4.0` 没有 py3.13 轮子（`Failed building wheel for av`） | **绕开 av**：ffmpeg 解 `-f f32le -ac 1 -ar 16000` 裸流 → `np.frombuffer` → 直接喂 `model.transcribe(array)` |
| E2 | 中文识别老出繁体 | whisper 中文输出的常见倾向 | `zhconv.convert(text,'zh-cn')` |
| E3 | 人名/昵称老识别错 | 缺上下文提示 | `initial_prompt` 里塞一句场景描述（人名、口癖、关系） |
| E4 | 音色服务在自己的终端里正常，脚本一调就 `ECONNREFUSED` | 子进程跟着父进程被回收（见 A9） | `cmd /c start` 脱钩；启动后**轮询端口**再继续 |
| E5 | 声音变成机械音 | GPT-SoVITS 没起来，插件退回 edge-tts | 看插件日志有没有 `GPT-SoVITS 没成（…）`；`fetch failed` = 9880 没人听 |

## G. 安全与合规（不是"坑"，是红线）

- **NapCat 与腾讯 ToS 冲突**，用小号；主号被风控就得不偿失。
- 抖音的点赞/评论/分享全是**用你的账号公开发布**，脚本默认给了保守上限（点赞 5/天、评论 1/天、分享只落私聊、不在评论区 @ 你）。
- RVC/翻唱音色必须是**你有权使用**的声音；GPT-SoVITS 音色同理。
- 任何 PAT、Cookie、Token **不要提交进 git**——本仓库的脚本全部从配置文件/环境变量读，仓库里没有任何密钥。
