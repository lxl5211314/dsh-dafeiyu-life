# DSH 接入 QQ：GitHub 现状调研（2026-10-30）

> 目的：搞清楚「把 DSH 接进 QQ」这件事，社区里最成熟、最"高级"的做法到底长什么样，
> 以及我们本机这套（NapCat + 本地源码版 `dsh-qq-onebot`）差在哪、值不值得换。
> 结论在前，证据在后；所有数字都是 2026-10-30 当场从 GitHub API 取的。

---

## 0. 一句话结论

**"最高级"不是一个插件，而是三种架构选择**：

| 你想要的 | 最高级的做法 | 代表 |
|---|---|---|
| 聊天质量与"人格活起来"（记忆、心情、斗图、语音、群聊插话） | **插件式 + 模块化内核**，每 QQ 会话一个 DSH 会话，人格走 preset，动态内容追加在 prompt 末尾 | `accomplish07zrh-eng/dsh-aurabot-qq` ★152 |
| 工程可靠性与可控性（白名单、额度、死信、可观测、MCP 工具子集） | **外部桥 + MCP**：桥接是独立进程，通过 DSH HTTP API 建会话，用 MCP server 给 agent 发 QQ 的能力 | `Derpyu520/qq-bridge` ★3275 |
| 不封号、长期挂着 | **QQ 官方 Bot API v2**（q.qq.com 注册机器人，独立 bot 账号） | `tencent-connect/dsh-qqbot` ★446 |

我们现在的这套属于**第四类：Host 插件直连 OneBot**（插件进程内自己建会话、自己收发）。
它是最省事、延迟最低的一条路，但社区里"最高级"的那些能力（记忆分层、诊断、花费看板、
群聊状态机、官方通道兜底）都不在这条路线的主干上。

**推荐的升级方向**：以 Aurabot（路线一）为能力模板、以 qq-bridge（路线二）为运维模板，
先把我们缺的"可观测 + 记忆分层 + 人格注入方式"补上；要不要真的换插件，见第 6 节的三档方案。

## 1. 检索方法（可复现）

- GitHub REST（本机唯一稳定可用的出口，`raw.githubusercontent.com` 与 jsDelivr 都被墙/超时）：
  - `GET https://api.github.com/search/repositories?q=<关键词>&sort=updated`
  - `GET https://api.github.com/repos/<owner>/<repo>/readme`（`Accept: application/vnd.github.raw` 直接拿 Markdown）
  - 关键词：`dsh-qq-onebot` / `dsh qq onebot` / `deepseek harness qq` / `dsh-onebot` / `dsh qq bot napcat` / `dsh-plugin qq` / `dsh qqbot`
- 坑：Windows PowerShell 5.1 里 `Invoke-WebRequest` 非交互模式会走 IE 引擎报
  `Windows PowerShell 处于非交互模式。朗读和提示功能不可用。` —— 一律改用 `Invoke-RestMethod`。
- 原文快照都留在 `dsh-handover\_research\*.md`（本报告引用的事实都能在那几个文件里复核）。

## 2. 四条技术路线

```
① Host 插件直连 OneBot（我们）
   QQ(个人号) ── NapCat/SnowLuma ──WS/HTTP──► dsh-qq-onebot(插件进程内) ──► DSH 会话 ──► LLM

② 外部桥 + MCP（qq-bridge）
   QQ(个人号) ── SnowLuma ──► bridge.js(独立进程) ──HTTP/Cookie──► DSH Web API
                                   └── MCP server ──► agent 自己调 qq_send_message 等

③ 官方 Bot API（腾讯官方插件 / roost）
   QQ 用户 ── QQ WebSocket 官方网关 ──► dsh-qqbot(插件) ──► ctx.agents ──► DSH 会话

④ 双轨（juju 分支 / 成熟商用思路）
   本地注入轨道（全群消息、分条斗图）+ 官方 Bot 轨道（合规不封号），共用人格/记忆/白名单
```

| 路线 | 延迟/复杂度 | 能力上限 | 封号风险 | 工程可控性 |
|---|---|---|---|---|
| ① 插件直连 | 最低/最简单 | 中（取决于插件作者） | 中（个人号协议端） | 中 |
| ② 外部桥 + MCP | 中/最复杂 | **最高**（agent 自主决定说几句、看不看、几时退场） | 中 | **最高**（白名单/额度/死信/看板） |
| ③ 官方 Bot | 中/注册最麻烦 | 低-中（被动 5 分钟/5 条，需主体认证） | **无**（官方允许） | 高 |
| ④ 双轨 | 高 | 最高 + 有兜底 | 低（官方轨托底） | 高 |

## 3. 代表项目逐个拆

### 3.1 `Derpyu520/qq-bridge` ★3275 —— 生态主干，外部桥 + MCP

- **不是 DSH 插件**，是独立 Node 进程（`bridge.js`，1 万行级），通过 DSH 的 HTTP 协议接进去：
  用本机持久化签名密钥**离线铸造会话 Cookie**、`/api/<namespace>/<method>` 斜杠 RPC、
  `/api/remote.mux` + `session/follow` 事件流、`session/control` 的队列投影读 inbox；
  会话模型按 `config.json` 的 `dsh.model` 逐会话 `session.selectModel` 固定。
  已在 **DSH 0.2.1-rc.2 上逐项复核**（和我们版本一致）。
- **agent 自主收发 QQ**：挂三个自带 MCP server —— `snowluma`（QQ 动作安全子集，发送强制白名单，
  支持 `replyToMessageId` 引用回复）、`snowluma-host`（**只有**只读探活，v0.1.5 起移除了
  `start_snowluma`/`stop_snowluma`，因为 SnowLuma EULA §5.4 禁止自动化脚本部署）、
  `web-search-safe`（只读 web_search/web_fetch + SSRF 防护，优先复用 DSH 自己那套 DeepSeek 搜索）。
- **四种运行模式**：`chat`（白名单安全聊天）/ `closed-agent`（仅主人，完整工具，可在 QQ 上遥控 DSH）/
  `reserved`（一代仿真：观望-活跃-试探-退场状态机、`[SILENT]` 潜水、按空格分句）/
  `reserved2`（二代仿真：AI 用 `qq_get_unread_messages` / `qq_send_message` 自己决定看不看、说几条、几时退场）。
- **控制台 3100**：十个页面，含 **令牌与花费看板**（可下钻到每个群/每个好友/每一轮，
  显示缓存命中率、峰谷时段、按 DeepSeek 官方价目折算金额）、人格两层提示词分开编辑
  （"仿真提示词"管行为协议、"人格提示词"管人设语气，后者保存即生效）、会话初始提示词只注入一次。
- **可靠性**：白名单/黑名单、`ackMessage`、`sendDelayMs` 防频控、端点自愈（换号后跟随新端口/token）、
  IPv4 优先 + 逐地址故障切换（修掉 IPv6 白等 20 秒）、单条消息 8MB/64MP/5 张上限。
- **代价**：要跑一个额外进程；要同步 DSH 的 Web 地址（`dsh.baseUrl`，默认 3080 —— 我们是桌面版，
  端口是随机的）；`node scripts/setup-dsh.mjs` 会往 profile 里装两个 preset + 挂 MCP，改动面比插件大。

### 3.2 `accomplish07zrh-eng/dsh-aurabot-qq` ★152 —— "大肥鱼本鱼"，能力天花板

**这个就是我们人设的原型项目**：标题直接写「住在 QQ 里的大肥鱼」，默认人格文件 `personas/dafeiyu.md`。

- **架构**：`QQ ⇄ SnowLuma/任意 OneBot v11 ⇄ Aurabot 插件 ⇄ DSH 会话（自带 preset + 人格）`。
  每 QQ 私聊/群 = 一个 DSH 会话，统一归到侧栏「Aurabot · QQ」工作区，可点开看她想了什么、调了什么工具、直接插话。
- **模块化内核**（`src/core/modules.js`）：12 个内置模块，每项本事都能关/换/复制改写；
  模块注册的工具、上下文、规则、命令、事件、定时任务、接口都记在它名下，停用时一起撤；
  用户模块放数据目录 `modules/`，升级不覆盖、保存即热重载、出错隔离。聊天主流程留了
  6 个改写挂钩（群聊决定、提示词、回复拆条、最终发送、模型选择、人格规则）。
- **人格注入**（关键手法）：`cordis.patch.yml` 自带两个 preset —— `aurabot-private`（主人私聊，完整工具）/
  `aurabot-social`（群聊与其他人，**没有任何本地工具**）；人格走 `@deepseek-ai/dsh-persona` 放在
  系统提示词最前，文本来自变量 `{{aurabot_persona}}`，换人格不用重建 preset。
- **动态内容不破坏缓存**：心情、记忆用 `agent.ctx.systemPrompt.context()` 追加在**对话末尾**（不是改前缀）。
- **记忆**：本地索引（中文二元切词 + BM25），按「关于当前说话人」「重要程度」「遗忘曲线」加权；
  来源 = 自己记的 + 每天两次从聊天/空间整理的 + 自己的经历 + 空间日记 + 手动加的；
  新事实先与旧记忆比对（补充则合并、过时则标"已过时"不删）；每人一张常驻「人物小档案」+ 相处经验 + 说话方式。
- **群聊**：停顿几秒算一段，回上一段时新消息先攒着；给的是"这段谁说了什么 + 之前聊什么"，
  新消息带编号可引用；合并转发展开；拍一拍当对话并能戳回去；被叫必回，没被叫按相关度插话 + 防刷屏刹车。
- **其他重活**：心情（关键词/模型判 + 半衰期回归，实际影响发表情/语音概率与回复快慢）、
  表情包（只收真表情，尺寸/宽高比/体积/MD5/小时限额数道关，视觉模型起备注存自定义表情）、
  语音（edge-tts 独立 venv，可换 CosyVoice/GPT-SoVITS，Windows 自带语音兜底；ASR 用 QQ 自带转文字再退 `speechToText`）、
  **翻唱**（网易云 → 截段 → audio-separator → RVC(Applio) → ffmpeg 混音 → 语音条）、
  **QQ 空间**（用专用后台会话写日记、按整串评论回一次、概率点赞）、
  **刷抖音**（独立浏览器 profile + CDP，窗口放屏幕外，走页面内 fetch 让抖音自己签名，不读屏；
  点赞/评论在弹层里按 video id 找按钮，成功以接口回执为准；每天上限、操作间隔、新号减半）、
  **B 站**（WBI 签名搜索、读简介字幕热评、按人格评论/私聊分享/记住）。
- **数据**：`%USERPROFILE%\.dsh\plugins-data\aurabot\`（配置/人格/表情/日记/记忆/日志/自写模块），
  重装升级不丢。安装在 Windows 一条命令：`dsh plugin --profile desktop add github:accomplish07zrh-eng/dsh-aurabot-qq`。
- **安全默认**：总开关关 + 试运行开；每个越权操作（改资料、群管、点歌生图）单独设
  关/仅主人私聊/所有人，执行前按最新设置再查一遍。

### 3.3 `tencent-connect/dsh-qqbot` ★446 —— 官方路线

- 走 QQ 官方 Bot API v2（`bot.q.qq.com/wiki`），**扫码绑定**（端内设置页或终端二维码），
  凭据自动落到 profile 的 `cordis.patch.yml`，之后无需再扫。
- 架构干净：`ctx.agents` + `inject = ['agents']`，每 QQ 私聊/群一个独立 Agent，`sessionIdleTimeout` 回收；
  sessionKey `qqbot:${appId}:${scope}:${peerId}`，新会话铸造 UUID 并持久化，重启按持久化 id 恢复。
- 工程细节很全：`ask_user_question` 转成内联按钮（点一个其余变灰）、`approval/request` 转成「允许/拒绝」、
  富媒体下载 + 视觉理解（`qqbot_describe_image`）、`qqbot_send_file`（默认路径白名单）、
  Markdown 切分（代码块/表格感知）、流式输出（群聊不流式）、被动回复 msgid 缓存 + 限流、
  内置 `/new` `/compact` `/model` `/preset` `/stop` `/bot-ping` 等命令。
- **限制**：必须是官方注册的机器人（AppID/AppSecret，要主体认证；个人主体通常只能自建群），
  默认只收 @，被动回复窗口 5 分钟 / 5 条。
- 生态里还有 `tdcq9594/dsh-roost` ★8 走另一条官方通道（Roost 内核 + ai-chat 插件）：
  它的亮点不在传输，而在**治理**——逐条权限判定（主人全工具 / 管理员只聊天 / 普通成员只聊天 /
  身份不明兜底只聊天，两层：提示词告诉 AI 谁在说话 + 按档位收工具）、三层记忆（跨群事实 + 日记三级衰减 +
  知识图谱双时态）、凌晨巩固、压缩前记录缓存命中率、667 条测试、九页面板。

### 3.4 `Yuuyuko-uu/dsh-qq-bridge` ★133 —— "不用 BOT，两边都通"

- 反向思路：不是"机器人接群"，而是**把 DSH 里那个会话和 QQ 打通** ——
  她在 DSH 里说完一整轮的最后一句 → 发到你填的 QQ；你在 QQ 里说的话 → 4 秒轮询灌进目标会话。
- 只依赖 OneBot 11 **HTTP** 的 6 个接口（send_private_msg / send_group_msg / get_login_info /
  get_friend_msg_history / get_group_msg_history），不碰协议、不连 WS。
- 细节做得实在：语音条转文字（自带 SenseVoice `asr_cli.py`）、图片双向传（收的图存
  `~/.dsh/qq-bridge-inbox/`，回发用**原图**避免 GIF 变静态）、分享卡片解析出标题与 BV 号、
  合并转发最多展开 2 层、markdown 图当贴纸发、"回复门槛"（先判断这条是不是在跟我说话，
  不是就 `agent.cancel` 静音）+ 工具只在被 QQ 叫醒后 10 分钟内有效。
- 安全默认：**总开关关、试运行开**；配置在 `%USERPROFILE%\.dsh\qq-bridge-config.json`。
- 它的 README 还顺手写了我们这边真踩过的坑：profile `package.json` **UTF-8 带 BOM** 会让 DSH
  报 `Unexpected token '﻿'` / `is not valid JSON` / `readProfileManifest` —— 和我们文档里的
  "手动改 profile 一律 UTF-8 无 BOM"是同一条。

### 3.5 `juju114514/qq-bridge` —— 双轨样本（★0，但作者与 10 人小圈子长期自用）

- 唯一把 **本地注入 + 官方 Bot 两条轨道同时跑** 的开源实现，共用一套人格卡/记忆/工具/白名单，
  只在外层换协议；`gateway-select` 自动识别 SnowLuma 与 NapCat，一个挂了 60 秒冷却降级。
- 能力清单是生态里最长的：人物库（身份只认 QQ 号、关系升档要"消息数 + 活跃天数"双达标、
  `qq_people_note` 能记事也能纠错）、`/自检`（网关/DSH/队列/cookies 一屏）、
  **`/诊断`（这条消息为什么没回：闸门→暂停→唤醒→投递逐段给判定）**、
  视频降维（9 帧 3×3 故事板 + 音轨 ASR）、B站/抖音/快手/小红书/YouTube 链接白名单、
  死信队列可重放、外部触发 `POST /api/inject`、Docker、schema 迁移前自动备份、官方通道实例互斥。
- 它明说的取舍：官方通道语音未实现（要 silk 转码）、多媒体部分实现、没有多用户权限体系。
- 兄弟分支值得知道的：`h-D-ACE/dsh-qq` ★82（TOTP 三级权限、控制中心、定时任务，
  "要给一群人用"看它）、`qqbot-hub/qqbot-plugins`（给 SnowLuma + qq-bridge + DSH 补 MCP 插件层，
  50 个插件 / 84 个工具，网页点一下装成 AI 可调用的 MCP 工具）。

## 4. "最高级"到底高级在哪：12 条可借鉴的具体做法

1. **每 QQ 会话 = 一个 DSH 会话，映射持久化**（`state/sessions.json` / `model-prefs.json`），
   断线重连、重启后接得上；会话统一归组到一个工作区，人能点进去看它想了什么。三个项目都这么做。
2. **人格放 preset，不塞进每轮 prompt**：`cordis.patch.yml` 里两条 preset
   （主人私聊=全工具 / 群聊=零本地工具），人格用 `@deepseek-ai/dsh-persona` 放在系统提示词最前。
3. **动态内容追加在 prompt 末尾**（`agent.ctx.systemPrompt.context()`），不碰前缀 → 前缀缓存不被打穿。
   这是记忆/心情类插件最容易被忽略的性能点。
4. **权限双层**：提示词层告诉 AI"谁在说话、什么档位"，硬限制层按档位收工具；认不出身份一律最低档。
5. **发言走工具而不是被动转发**：`qq_send` / `qq_close` 由模型自己调，调几次就是几条独立消息，
   "说完要不要退场、一句都不说"都归它决定 —— 这是拟人的分水岭。
6. **群聊按"段"处理**：停顿几秒算一段，回时新消息先攒着，给的是"这段谁说了什么 + 之前聊什么"。
7. **记忆分层 + 遗忘曲线 + 人物小档案**，新事实与旧记忆比对（合并/标过时而不是删）。
8. **可观测**：`/诊断` 逐段判定"为什么不回"、`/自检` 看整条链路、token 花费下钻到每一轮并算缓存命中率。
9. **安全默认关**：总开关关 + 试运行开；越权动作（改资料、群管、点歌、生图）逐项授权，执行前复查。
10. **出站统一过闸**：模型不直连 QQ，所有发送过白名单/额度/脱敏/令牌校验 —— 被提示词注入也刷不了屏。
11. **MCP 工具子集**：只把"查状态/查消息/发消息"这类安全子集挂给 agent，进程控制（启停网关）一律不给，
    还顺带守住上游 EULA（SnowLuma 禁止自动化部署 → 只探测不部署）。
12. **降维而不是硬塞**：模型看不了视频 → 抽 9 帧故事板 + 音轨 ASR；抖音链接分 `meta`（秒回元数据）/
    `transcript` / `storyboard` 三档，用户自己选成本。

## 5. 我们本机这套 vs 上面

现状（详见 `README.md` §6.3）：NapCat 4.18.41（WS 3001 / WebUI 6099）+ 本地源码版
`dsh-qq-onebot`（`link:D:/aaa_dsh_data_storage/napcat-bridge/dsh-qq-onebot/package`，v1.0.0）
装在 **qqbot** profile；配置在 `%USERPROFILE%\.dsh\profiles\qqbot\cordis.patch.yml`（204 行）；
20 个 qq 工具；TTS edge（`zh-CN-XiaoyiNeural`，-8%）；主动消息 8 次/天；表情包库 **0 张**；
插件设置页 `http://127.0.0.1:34569/api/dsh-qq`。**端到端从未真正验证过（链路在线 ≠ 收到过消息）。**

| 高级做法 | 我们 | 差距 |
|---|---|---|
| 每 QQ 会话一个 DSH 会话 | ✅ `isolateByPeer: true` + `sessions.json` | 无 |
| 人格注入（preset / 变量） | ⚠️ `personaFile` 热加载 + `personaPrefix: ''` | 只有一条 preset（`minimal`），没有私聊/群聊分档 |
| 动态内容不破缓存 | ❓ 未知（插件内部实现） | 需读源码确认 |
| 权限双层 | ⚠️ `ownerIds` + `requireMention` | 没有"管理员/普通成员/身份不明"三档，群友默认能拿到本地工具 |
| 发言走工具（自主分条/退场） | ✅ 有 `qq_send` / `qq_react` / `qq_recall` 等 20 个 | 群聊唤醒仍是名字唤醒 + 120 秒窗口，偏被动 |
| 群聊按段处理 | ⚠️ `mergeWindowMs: 4000` | 有合并窗口，但没有"段上下文 + 新消息编号" |
| 记忆分层/遗忘曲线/人物档案 | ❌（DSH 级有 dsh-mnemon + billion-context，但**不是 QQ 侧人物档案**） | 结构性缺失 |
| 诊断/自检命令 | ❌ 只有日志 | 结构性缺失，排障全靠看 UTF-8 日志 |
| token 花费看板 | ❌ | 有 dsh-cost-meter 可另装，但不是 QQ 分群下钻 |
| 安全默认关 | ⚠️ 插件默认就发（`proactiveEnabled: true`） | 缺"总开关 + 试运行" |
| 视频/链接降维 | ❌ | 结构性缺失（也是我们查抖音查不动的同一问题） |
| 官方通道兜底 | ❌ | 只有非官方轨道，存在封号风险 |

**一句话**：我们是"能跑起来的最小可用"，对面是"能长期挂着、坏了能自己说为什么"的产品级实现。

## 6. 三档方案（按代价从小到大）

### A. 保守：留下现在这套，只补三件事（半天）

1. **先把端到端跑通**（发一条私聊 + 群里 @ 一次，看日志有没有 `agent` 回合），这是所有能力的前提。
2. **补权限**：给群聊换一个"零本地工具"的 preset，`ownerIds` 之外不给 shell/文件工具。
3. **补可观测**：加一次 `/诊断` 式的自检脚本（网关 3001 活着？`get_login_info` 是谁？队列有没有积压？）。
   —— 这三件事不换插件也能做，收益最大。

### B. 进阶：换 Aurabot（半天到一天，风险中）

- 一条命令装：`dsh plugin --profile qqbot add github:accomplish07zrh-eng/dsh-aurabot-qq`。
- 它接 NapCat 是官方支持的（"接我已有的 OneBot 机器人：NapCat、LLOneBot、Lagrange 都行"），
  我们现有的 NapCat 4.18.41 不用动；人格可以继续用我们的 `大肥鱼人设.md`（它自带 dafeiyu.md）。
- 得到：模块化内核、私聊/群聊双 preset、群聊按段、三层记忆 + 人物档案、心情、表情包、语音/翻唱、
  空间、B站、抖音、面板里能看"她想了什么"。
- 代价：功能面极大 = 需要的模型能力（视觉/语音）也多；它自己的数据目录全新，我们现在的
  `QQ会话/` 记忆与聊天记录要另行迁移；**它和我们现有的 dsh-qq-onebot 不能同时占 3001**（要卸一个）。

### C. 彻底：qq-bridge（外部桥 + MCP）或官方通道（一到两天，风险高/注册麻烦）

- C1 `Derpyu520/qq-bridge`：能力与工程性天花板，但要额外一个进程、要指向 DSH 的 Web 地址
  （我们是桌面版，端口随机，需固定或每次同步）、要跑 `setup-dsh.mjs` 往 profile 装 preset + 挂 MCP。
- C2 `tencent-connect/dsh-qqbot`：零封号风险，但要去 q.qq.com 注册机器人（主体认证），
  且能力受官方被动回复窗口限制 —— 适合"要长期公开挂着、不能封号"的场景，不适合"假装真人"。
- juju 式双轨是两者的组合，工作量最大，除非确定要长期 7×24 对外。

**我的建议**：先做 A 的第 1 条（端到端验证，成本最低、信息量最大），
再决定是走 B（要人格活起来）还是 C2（怕封号）。别一上来就换，我们现在连"能不能收到消息"都还没证明。

## 7. 风险与合规（每个项目都提，必须写下来）

- **非官方轨道（NapCat / SnowLuma + 个人号）违反腾讯 ToS**，有封号风险 → 一律用小号，
  不要让主号承担。
- SnowLuma EULA §5.4 禁止"通过自动化脚本部署"，所以成熟项目（qq-bridge、Aurabot）都
  **只探测/只启停你自己装好的那份，不代替你下载安装、不代你同意协议**。我们用的是 NapCat，
  同理：自己装、自己扫码，插件只管连。
- 把 agent 接进 QQ **等于把账号控制权交给模型**：白名单、额度、出站脱敏、总开关默认关，
  这四道闸一个都不能省。
- 官方 Bot 通道要主体认证；个人主体一般只能拉进自建群。想"公开群里有个 AI"，先走官方。
